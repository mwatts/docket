## Goal

When `docket done <id>` is run, sync the acceptance criteria checkboxes from `.docket/current.json` back to the bug's markdown file before marking it complete.

## Acceptance Criteria

- [x] `docket done` reads acceptance criteria state from `.docket/current.json`
- [x] `docket done` updates the bug file's checkboxes to match
- [x] `docket done` then marks status as done
- [x] Works correctly even if current.json has extra log entries
- [x] Bug fvsc has its acceptance criteria synced (test case - this bug fixes it)

## Context

During `docket work`, the skill updates `.docket/current.json` with progress - checking off acceptance criteria and adding log entries. But when work completes, this state doesn't flow back to the canonical bug file.

Current model:
- `current.json` = scratch pad during work
- bug file = source of truth, should be updated by `docket done`
- Event logs (m4ef) will eventually replace this model

This is a stopgap until event logs are implemented.
